# VCF-Allelic-Depth-Ratio-Filter
A C++ program to filter multi-sample VCF (Variant Call Format) files based on allelic depth (AD) ratios. Supports both **standard VCF format** and **VarScan2 VCF format**.

## Features

- Filter multi-sample VCF files based on allelic depth (AD) ratios or frequencies
- **Support for both standard VCF and VarScan2 VCF formats**
- Customizable purity thresholds for homozygous calls
- Customizable ratio ranges for heterozygous calls
- Selective sample evaluation (include or ignore specific samples)
- Detailed logging with filtering statistics
- Efficient processing of large VCF files

## Quick Start

```bash
# Compile
make

# Filter standard VCF
./vcf_filter -v input.vcf -s samples.txt -o filtered.vcf

# Filter VarScan2 VCF
./vcf_filter -v varscan.vcf -s samples.txt -o filtered.vcf -t varscan
```

### Full Command-Line Options

```bash

  -v, --vcf FILE          Input multi-sample VCF file
  -s, --samples FILE      Sample list file (tab-delimited)
  -o, --output FILE       Output filtered VCF file

Optional arguments:
  -t, --vcf-type TYPE     VCF format type: 'standard' or 'varscan' (default: standard)

  -m, --het-min PCT       Heterozygous minimum ratio (default: 40.0)
  -M, --het-max PCT       Heterozygous maximum ratio (default: 60.0)
  -h, --help              Display help message
```

## VCF Format Types

The program supports two VCF format types, selected with the `-t` or `--vcf-type` option:

### Standard VCF Format (default)

**How it works:**
- Uses the AD (Allelic Depth) field with comma-separated allele depths
- Program calculates ratios from AD values
- Example FORMAT: `GT:AD:DP`
- Example data: `0/1:50,50:100` (50 ref reads, 50 alt reads)

**When to use:**
- Standard variant callers (GATK, FreeBayes, etc.)
- VCF files with comma-separated AD fields
- Default behavior if no `-t` flag specified

**Usage:**
```bash
./vcf_filter -v input.vcf -s samples.txt -o output.vcf
# or explicitly:
./vcf_filter -v input.vcf -s samples.txt -o output.vcf -t standard
```

### VarScan2 VCF Format

**How it works:**
- Uses separate RD (Reference Depth) and AD (Alternate Depth) fields
- Uses FREQ (Frequency) field with percentage string
- Program uses FREQ directly without calculation
- Example FORMAT: `GT:GQ:SDP:DP:RD:AD:FREQ:PVAL:...`
- Example data: `0/1:22:100:100:50:50:50%:0.001:...`

**When to use:**
- VCF files generated by VarScan2
- VCF files with FREQ field containing percentages

**Usage:**
```bash
./vcf_filter -v varscan.vcf -s samples.txt -o output.vcf -t varscan
```

### Format Comparison

| Feature | Standard VCF | VarScan2 VCF |
|---------|--------------|--------------|
| Format flag | `-t standard` (default) | `-t varscan` |
| Allele depth | AD=ref,alt (comma-separated) | RD=ref, AD=alt (separate fields) |
| Frequency | Calculated from AD | FREQ field (e.g., "50%") |
| Filtering basis | AD ratios | FREQ percentage |
| Typical purity | 95-100% | 80-90% |
| Typical het range | 40-60% | 20-80% |

## Input Files

### VCF File

**For Standard VCF:**
- Multi-sample VCF file (version 4.0 or later)
- Must have GT (genotype) field
- Must have AD (allelic depth) field with comma-separated values

Example:
```
chr1  1000  .  A  G  100  PASS  .  GT:AD:DP  0/0:100,0:100  0/1:50,50:100
```

**For VarScan2 VCF:**
- Multi-sample VCF file generated by VarScan2
- Must have GT (genotype) field
- Must have RD (reference depth) field
- Must have AD (alternate depth) field
- Must have FREQ (frequency) field with percentage

Example:
```
chr1  1000  .  A  G  .  PASS  .  GT:RD:AD:FREQ  0/0:100:0:0%  0/1:50:50:50%
```

### Sample List File

Tab-delimited text file with two columns:
1. Sample name (must match VCF header exactly)
2. Symbol indicating whether to evaluate the sample

**Symbols:**
- `+`, `1`, `include`, or `INCLUDE` = Evaluate this sample
- Any other symbol (e.g., `-`, `ignore`, `skip`) = Ignore this sample

**Example sample list:**
```
Sample1	+
Sample2	include
Sample3	-
Sample4	1
Sample5	ignore
Sample6	INCLUDE
```

In this example, Sample1, Sample2, Sample4, and Sample6 will be evaluated for filtering, while Sample3 and Sample5 will be ignored.

## Filter Logic

### Standard VCF Mode

#### Homozygous Calls (0/0, 1/1, 2/2, etc.)

For homozygous genotypes, the program checks that the called allele has the required purity percentage.

**Examples with default 100% purity:**
- `0/0` with `AD=100,0` → **PASS** (100% reference)
- `0/0` with `AD=99,1` → **FAIL** (99% reference < 100% threshold)
- `1/1` with `AD=0,100` → **PASS** (100% alternate)
- `1/1` with `AD=1,99` → **FAIL** (99% alternate < 100% threshold)

**With custom 95% purity (`-p 95`):**
- `0/0` with `AD=96,4` → **PASS** (96% reference ≥ 95% threshold)
- `0/0` with `AD=94,6` → **FAIL** (94% reference < 95% threshold)

#### Heterozygous Calls (0/1, 1/2, etc.)

For heterozygous genotypes, the program checks that at least one allele falls within the acceptable ratio range.

**Examples with default 40-60% range:**
- `0/1` with `AD=50,50` → **PASS** (50% is within 40-60%)
- `0/1` with `AD=40,60` → **PASS** (both 40% and 60% are within range)
- `0/1` with `AD=60,40` → **PASS** (both 60% and 40% are within range)
- `0/1` with `AD=70,30` → **FAIL** (70% > 60%, 30% < 40%)
- `0/1` with `AD=35,65` → **FAIL** (35% < 40%, 65% > 60%)

**With custom 35-65% range (`-m 35 -M 65`):**
- `0/1` with `AD=70,30` → **FAIL** (70% > 65%, 30% < 35%)
- `0/1` with `AD=65,35` → **PASS** (both 65% and 35% are at boundaries)

### VarScan2 Mode

#### Homozygous Reference (0/0)

For homozygous reference calls, FREQ represents variant frequency, so it should be near 0%.

**How it works:**
- FREQ shows the percentage of variant (alternate) reads
- For true 0/0 calls, FREQ should be close to 0%
- Allowed variant frequency = 100% - homozygous purity

**Examples:**
- With 100% purity (allows 0% variant reads):
  - `0/0` with `FREQ=0%` → **PASS**
  - `0/0` with `FREQ=5%` → **FAIL**
  
- With 95% purity (allows up to 5% variant reads):
  - `0/0` with `FREQ=0%` → **PASS**
  - `0/0` with `FREQ=4%` → **PASS**
  - `0/0` with `FREQ=6%` → **FAIL**

- With 90% purity (allows up to 10% variant reads):
  - `0/0` with `FREQ=8%` → **PASS**
  - `0/0` with `FREQ=12%` → **FAIL**

#### Homozygous Alternate (1/1)

For homozygous alternate calls, FREQ should be near 100%.

**Examples:**
- With 100% purity:
  - `1/1` with `FREQ=100%` → **PASS**
  - `1/1` with `FREQ=95%` → **FAIL**
  
- With 95% purity:
  - `1/1` with `FREQ=95%` → **PASS**
  - `1/1` with `FREQ=94%` → **FAIL**

- With 80% purity:
  - `1/1` with `FREQ=82%` → **PASS**
  - `1/1` with `FREQ=78%` → **FAIL**

#### Heterozygous (0/1)

For heterozygous calls, FREQ should fall within the specified range.

**Examples with 40-60% range:**
- `0/1` with `FREQ=50%` → **PASS**
- `0/1` with `FREQ=45%` → **PASS**
- `0/1` with `FREQ=32%` → **FAIL**
- `0/1` with `FREQ=70%` → **FAIL**

**Examples with 20-80% range:**
- `0/1` with `FREQ=25%` → **PASS**
- `0/1` with `FREQ=75%` → **PASS**
- `0/1` with `FREQ=15%` → **FAIL**
- `0/1` with `FREQ=85%` → **FAIL**

### Variant Retention Logic

A variant is **retained** only if:
1. All samples marked for evaluation (include/+/1) pass the filters, OR
2. The sample has missing data (./.) or zero depth (not filtered)

A variant is **filtered out** if:
- ANY sample marked for evaluation fails the AD/frequency ratio checks

Samples marked as "ignore" are not evaluated and don't affect filtering decisions.

## Recommended Parameters

### Standard VCF

| Use Case | Homozygous (-p) | Heterozygous (-m/-M) | Command |
|----------|----------------|---------------------|---------|
| Very strict | 100 | 45-55 | `-p 100 -m 45 -M 55` |
| **Default/Strict** | 100 | 40-60 | (default settings) |
| Moderate | 95 | 35-65 | `-p 95 -m 35 -M 65` |
| Relaxed | 90 | 30-70 | `-p 90 -m 30 -M 70` |
| Very relaxed | 85 | 25-75 | `-p 85 -m 25 -M 75` |

**Recommendations:**
- Clinical applications: Use strict or very strict
- Research applications: Use moderate to relaxed
- High-quality data: Can use stricter settings
- Noisy data: Use more relaxed settings

### VarScan2 VCF

| Use Case | Homozygous (-p) | Heterozygous (-m/-M) | Command |
|----------|----------------|---------------------|---------|
| Conservative | 90 | 35-65 | `-t varscan -p 90 -m 35 -M 65` |
| **Recommended** | 85 | 25-75 | `-t varscan -p 85 -m 25 -M 75` |
| Moderate | 85 | 20-80 | `-t varscan -p 85 -m 20 -M 80` |
| Permissive | 80 | 15-85 | `-t varscan -p 80 -m 15 -M 85` |
| Very permissive | 75 | 10-90 | `-t varscan -p 75 -m 10 -M 90` |

**Why VarScan needs different parameters:**
- VarScan is generally more permissive than other variant callers
- Often reports lower frequencies for heterozygotes
- Default strict settings (100%, 40-60%) are too stringent for most VarScan data
- Start with recommended settings and adjust based on your data

## Troubleshooting

### Common Issues for Both Formats

#### "Sample 'X' not found in VCF"
**Problem:** Sample name mismatch
**Solution:**
- Ensure sample names in the sample list exactly match those in the VCF header
- Check for extra spaces or different capitalization
- Use: `grep "^#CHROM" input.vcf` to see VCF sample names

#### "Cannot open VCF file"
**Problem:** File access issue
**Solution:**
- Verify the file path is correct
- Ensure you have read permissions: `ls -l input.vcf`
- Check if the file exists

#### "Malformed VCF line"
**Problem:** VCF format issue
**Solution:**
- Ensure your VCF file is properly formatted
- Check that all required columns are present
- Verify the VCF has FORMAT and sample columns
- Try: `head -20 input.vcf` to inspect format

### Standard VCF Issues

#### All variants filtered
**Problem:** Parameters too strict
**Solution:**
```bash
# Try with relaxed parameters
./vcf_filter -v input.vcf -s samples.txt -o output.vcf -p 90 -m 30 -M 70
```

#### Missing AD field error
**Problem:** VCF doesn't have AD field
**Solution:**
- Check if your VCF has AD field: `grep "##FORMAT=<ID=AD" input.vcf`
- Some VCFs use different field names - check the FORMAT column
- Consider if this is actually a VarScan VCF (use `-t varscan`)

### VarScan2 VCF Issues

#### All variants filtered with default settings
**Problem:** Default parameters (100%, 40-60%) too strict for VarScan
**Solution:**
```bash
# Use VarScan-appropriate parameters
./vcf_filter -v input.vcf -s samples.txt -o output.vcf \
             -t varscan -p 85 -m 20 -M 80
```

#### Error: "FREQ field not found"
**Problem:** Not a VarScan VCF or wrong format
**Solution:**
- Verify it's a VarScan VCF: `grep "##FORMAT=<ID=FREQ" input.vcf`
- Check the source line: `grep "##source=" input.vcf`
- If no FREQ field, use standard mode: remove `-t varscan` flag

#### Too many homozygous reference variants filtered
**Problem:** VarScan reports background variant frequencies
**Solution:**
```bash
# Lower the purity requirement (allow more variant reads)
./vcf_filter -v input.vcf -s samples.txt -o output.vcf \
             -t varscan -p 85  # Allows up to 15% variant reads in 0/0 calls
```

#### Too many heterozygous variants filtered
**Problem:** VarScan heterozygotes often have unbalanced allele frequencies
**Solution:**
```bash
# Widen the heterozygous range
./vcf_filter -v input.vcf -s samples.txt -o output.vcf \
             -t varscan -m 15 -M 85  # Allows 15-85% range
```

### Deciding on Parameters

#### Strategy 1: Top-Down Approach
Start strict and relax if needed:
```bash
# 1. Try strict
./vcf_filter -v input.vcf -s samples.txt -o test1.vcf -p 95 -m 40 -M 60

# 2. If retention <50%, try moderate
./vcf_filter -v input.vcf -s samples.txt -o test2.vcf -p 90 -m 35 -M 65

# 3. If still low, try relaxed
./vcf_filter -v input.vcf -s samples.txt -o test3.vcf -p 85 -m 30 -M 70
```

#### Strategy 2: Bottom-Up Approach
Start permissive and tighten:
```bash
# 1. Very permissive (should retain >90%)
./vcf_filter -v input.vcf -s samples.txt -o test1.vcf -p 80 -m 20 -M 80

# 2. Moderate
./vcf_filter -v input.vcf -s samples.txt -o test2.vcf -p 85 -m 30 -M 70

# 3. More stringent
./vcf_filter -v input.vcf -s samples.txt -o test3.vcf -p 90 -m 35 -M 65
```

#### Reading the Log File to Guide Adjustments

Look at the "Filter Reasons" section:

```
Filter Reasons:
  Sample Sample1: Hom ref has variant freq 12.0% > 10.0%: 150
  Sample Sample1: Het variant freq 35.0% outside 40.0-60.0%: 80
```

**Interpretation:**
- Many "Hom ref has variant freq" → Lower purity (-p value)
- Many "Het variant freq outside" → Widen het range (-m/-M values)

## Advanced Usage

### Batch Processing

```bash
# Create a script to process multiple files
for vcf in data/*.vcf; do
    base=$(basename "$vcf" .vcf)
    ./vcf_filter -v "$vcf" -s samples.txt \
                 -o "filtered/${base}_filtered.vcf" \
                 -l "logs/${base}.log" \
                 -p 90 -m 30 -M 70
done
```

### Comparing Parameter Sets

```bash
# Test multiple parameter combinations
for purity in 100 95 90 85; do
    for min in 40 35 30 25; do
        max=$((100 - min))
        output="test_p${purity}_m${min}_M${max}.vcf"
        log="test_p${purity}_m${min}_M${max}.log"
        ./vcf_filter -v input.vcf -s samples.txt \
                     -o "$output" -l "$log" \
                     -p "$purity" -m "$min" -M "$max"
        
        # Extract retention rate
        retention=$(grep "Retained variants" "$log" | awk '{print $4}')
        echo "p=$purity m=$min M=$max: $retention"
    done
done
```

## Known Limitations

- Assumes diploid genotypes (0/0, 0/1, 1/1)
- Requires GT field in VCF FORMAT
- For standard VCF: Requires AD field
- For VarScan VCF: Requires RD, AD, and FREQ fields
- Processes variants sequentially (not parallel)
- Loads entire VCF header into memory
- Does not support compressed input/output (.vcf.gz)
